# Phase 17 — UI Design Contract

> Visual and interaction contract for Phase 17: Graph as Entity-Scoped Tab in Detail Pane.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Locks the gaps left open by SPEC.md, CONTEXT.md, and the four sketch winners (001-D, 002-D, 003 applied, 004-C). All tab-strip placement, density, modal-round-trip, and tab-persistence semantics are pre-locked upstream — this UI-SPEC turns those into concrete Tailwind classes, ARIA roles, copy strings, and edge palette entries the executor can implement without ambiguity.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside tab buttons; toolbar action gaps |
| sm | 8px | Tab button vertical padding (LOCKED — SPEC + sketch 002-D); Source-tab toolbar inner padding |
| md | 16px | Source-tab body padding; modal header padding; takeover header padding |
| lg | 24px | Modal body inner padding (around the snippet/full source viewport) |
| xl | 32px | Modal viewport outer offset (~92% viewport leaves ~32-48px on each side at 1440-wide) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- **Tab strip height parity (LOCKED — SPEC Constraint)**: right-pane TabStrip total height MUST equal left-pane `EntityTabBar` height to the pixel so bottom borders align. Implementation: identical Tailwind classes — `px-3 py-2 text-xs` on the button, `border-b border-slate-200 dark:border-slate-700` on the container. Verified via DevTools MCP screenshot, both views, light + dark.
- **Modal sizing**: ~92% viewport (locked SPEC Requirement 9); concretely `w-[92vw] h-[92vh]` with `max-w-none` so the existing `EntityModal` shell does not constrain it.
- **Maximize/restore takeover**: full editor takeover hides `.editor-tree-pane` and `.editor-detail-pane` via `[data-overlay-takeover="true"]` attribute on the layout root; only the app header + project bar remain visible (D-11 — CSS toggle, no unmount, preserves Monaco scroll).
- **Source-tab toolbar height**: 32px tall (`h-8`) to keep it visually subordinate to the TabStrip above; sits flush below the entity header.

Source: SPEC §Constraints "bottom borders MUST align horizontally"; CONTEXT D-11; sketches 002-D, 004-C.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (normal) | 1.5 |
| Tab label | 12px (`text-xs`) | 500 (`font-medium`) | 1.4 |

| Modal header / takeover header | 14px (`text-sm`) | 600 (`font-semibold`) | 1.4 |

Notes:
- TabStrip label uses **sentence case** (LOCKED — sketch 001-D): "Detail", "Graph", "Source". Matches existing `EntityTabBar.tsx` casing pattern of "Classes / Properties / Individuals".

The 500 is required for parity with `EntityTabBar.tsx` (`font-medium`); we treat 500 + 600 as a single "emphasized" tier and 400 as default — within the "max 2 weight families" rule.

Source: existing `EntityTabBar.tsx`, sketch 001-D, SPEC Requirement 1 ("icon + sentence-case label").

## Color

60/30/10 split + semantic palette. No new tokens introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-slate-50 dark:bg-slate-900` | Editor canvas, panel backgrounds |
| Secondary (30%) | `bg-white dark:bg-slate-800` | Right-pane detail panel surface, modal surface, takeover surface |
| Accent (10%) | `primary-500 / primary-600` (`#0ea5e9 / #0284c7`) | Active tab underline + accent-tinted background fill, focus rings, primary toolbar action |
| Destructive | `red-600 / red-50` | Not used in this phase (no destructive actions) |

Accent reserved for (explicit list — never "all interactive elements"):
- **Active tab indicator** — 2px bottom border `border-b-2 border-primary-600 dark:border-primary-400` AND tinted background fill `bg-primary-50 dark:bg-primary-900/20` (LOCKED — SPEC Requirement 1: "accent underline + accent-tinted background fill"). The combination — underline + tint — is a deliberate visual departure from the left `EntityTabBar` (underline-only) so the right-pane strip reads as the *workspace mode selector* while the left strip reads as a *tree filter*. Users see at a glance which level of navigation they are in.
- **Active tab label color** — `text-primary-600 dark:text-primary-400`
- **Active tab icon color** — inherits from label (no separate accent)
- **Source-tab primary toolbar action** "Open full source" — `text-primary-600 dark:text-primary-400` with `hover:bg-primary-50 dark:hover:bg-primary-900/20`. Secondary action "Copy snippet" stays slate.
- **Modal `Maximize` / takeover `Restore` icon-buttons** — slate by default, `hover:text-primary-600 dark:hover:text-primary-400`. Not accent-filled (these are auxiliary controls, not primary actions).
- **Focus-visible ring on TabStrip buttons + toolbar buttons** — `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary-500/50 focus-visible:ring-offset-1 focus-visible:ring-offset-white dark:focus-visible:ring-offset-slate-800`

Inactive tab styling (matches `EntityTabBar.tsx` exactly):
- Label: `text-slate-500 hover:text-slate-700 dark:text-slate-400 dark:hover:text-slate-300`
- Background: transparent (no fill on inactive)
- No border-bottom indicator (only the strip's container border-bottom shows)

Disabled tab styling (e.g., Source tab in Standard mode — though this case is impossible in v1 since the tab is conditionally rendered, not disabled): `text-slate-300 dark:text-slate-600 cursor-not-allowed` — included for completeness if a future phase needs a "Source unavailable" disabled state.

Edge palette extension for new `edge_kind` values (D-06; lineage-philosophy from MEMORY: focus=blue, root=red, ancestor=gray, seeAlso=purple):

| edge_kind | Stroke | Dash | Label | Rationale |
|-----------|--------|------|-------|-----------|
| `subClassOf` (existing) | `#94a3b8` (slate-400) | solid | subClassOf | unchanged |
| `equivalentClass` (existing) | `#3b82f6` (blue-500) | `5 3` | equivalentTo | unchanged |
| `disjointWith` (existing) | `#ef4444` (red-500) | `5 3` | disjointWith | unchanged |
| `seeAlso` (existing) | `#9ca3af` (gray-400) | `2 4` | seeAlso | unchanged |
| **`domain`** (new) | `#94a3b8` (slate-400) | solid | domain | "ancestor-class" relationship — borrows subClassOf solid slate (acts as a structural connection from property to its anchoring class) |
| **`range`** (new) | `#94a3b8` (slate-400) | `4 2` | range | symmetric to domain but dashed to distinguish direction in property graphs |
| **`subPropertyOf`** (new) | `#64748b` (slate-500) | solid | subPropertyOf | structural ancestor (parallels subClassOf one shade darker so property hierarchies read distinctly when both are on screen) |
| **`rdfType`** (new) | `#0ea5e9` (primary-500 / blue) | solid | rdf:type | "this individual IS-A this class" — accent blue marks the most semantically strong assertion in an individual graph |
| **`sameAs`** (new) | `#a855f7` (purple-500) | `5 3` | sameAs | identity relation — borrows seeAlso family (purple per MEMORY); dashed to flag identity vs reference |
| **`objectProperty`** (new) | `#71717a` (zinc-500) | solid | `<predicate>` (literal local name) | generic individual-to-individual link; neutral zinc keeps focus on rdf:type accent |

Markers (arrowheads): `subClassOf`, `subPropertyOf`, `domain`, `range`, `rdfType`, `objectProperty` use `markerEnd: "url(#arrow-slate)"` (existing). `equivalentClass`, `disjointWith`, `seeAlso`, `sameAs` are markerless (matches existing convention for symmetric relations).

Edge stroke widths: `subClassOf` = 1.5 (existing emphasis on hierarchy); `subPropertyOf` = 1.5 (parallel emphasis); `rdfType` = 1.5 (semantic primary); all others = 1.

Source: existing `OntologyEdge.tsx`, MEMORY lineage-coloring philosophy, CONTEXT D-06.

## Visual Hierarchy

Primary focal point: **the right-pane body** (Detail form / Graph canvas / Source snippet) — this is the user's workspace. The TabStrip above it is a mode selector that frames the body without competing for attention.

Order of visual weight (top to bottom in the right pane):

1. **TabStrip** — tied for first. Sets context. Compact (text-xs, py-2) so it does not dominate, but accent-tinted active tab makes the current mode unmistakable.
2. **Entity header** — pip + name + IRI + Copy IRI button. Persists across all tab swaps (LOCKED — SPEC Requirement 1 acceptance: "entity header stays visible across tab swaps"). Sits directly below TabStrip.
3. **Tab body** — Detail form / Graph / Source. Fills remaining vertical space.

The Source tab's toolbar (Open full source + Copy snippet + line-comment) sits *between* the entity header and the Monaco viewport — visually a secondary band, not a third tab strip. 32px tall, slate background (`bg-slate-50 dark:bg-slate-900/50`), no border-bottom indicator (only a 1px slate-200/700 separator at its bottom edge).

Modal hierarchy (when "Open full source" overlay is up):

1. **Modal header** — title "Source — {entity local name}" + Maximize button + Close (✕). Solid `bg-white dark:bg-slate-800`, 1px slate-200/700 border-bottom, `font-semibold text-sm`.
2. **Modal body** — full Monaco editor of the entire `ontology.ttl`, scroll-positioned to the entity's start line with that line highlighted.
3. **Backdrop** — `bg-black/50` dim overlay.

Takeover hierarchy (after Maximize):

1. **App header + project bar** — unchanged, persists.
2. **Takeover header** — slim band immediately below the project bar: title "Source — {entity local name}" + Restore (⊟) button + Close (✕). Same typography as modal header.
3. **Takeover body** — full Monaco editor occupying the entire below-header space (where tree + detail used to be).

The Restore button only appears when `cameFromModal === true` (LOCKED — D-10, SPEC Requirement 9 acceptance: "Restore button is hidden when the takeover was NOT reached via Maximize").

## Component Inventory

### TabStrip (new — shared, used by both Standard + Developer right panes)

- Container: `<div role="tablist" className="flex border-b border-slate-200 dark:border-slate-700">`
- Each tab: `<button role="tab" aria-selected={...} aria-controls={...} id={...}>`
- Tab content: `<icon /> <span>{label}</span>` — icon at `h-3.5 w-3.5` (14px), label `text-xs font-medium`, gap `gap-1.5` (6px — between sketches' 4 and 8)
- Layout: `flex-1 px-3 py-2` per button (mirrors `EntityTabBar.tsx` density exactly so bottom borders align — LOCKED constraint)
- Active: `border-b-2 border-primary-600 bg-primary-50 text-primary-600 dark:border-primary-400 dark:bg-primary-900/20 dark:text-primary-400`
- Inactive: `text-slate-500 hover:text-slate-700 hover:bg-slate-50 dark:text-slate-400 dark:hover:text-slate-300 dark:hover:bg-slate-800/50`
- Focus-visible: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary-500/50 focus-visible:ring-inset`
- Icons (Lucide): `FileText` for Detail; `Network` (3-node graph glyph; if `Network` unavailable use `Workflow` or `GitBranch` — `Network` is the closest visual to the design contract's "3-node graph glyph") for Graph; `FileCode2` for Source (sketch 001 mentions `chevrons-left-right` but `FileCode2` reads more clearly as "source code" — Claude's discretion area per CONTEXT)
- Tab `id` pattern: `pane-tab-{detail|graph|source}` so `aria-controls` can point at the body panel by id `pane-panel-{detail|graph|source}`
- Props: `tabs: Array<{ id: 'detail' | 'graph' | 'source'; label: string; icon: LucideIcon }>`, `activeTab: PaneTab`, `onTabChange: (tab: PaneTab) => void`
- File location: `components/editor/PaneTabStrip.tsx` (sibling of `EntityTabBar.tsx` so the parallel is obvious)
- Naming: `PaneTabStrip` (not `TabStrip`) to disambiguate from `EntityTabBar` and any future generic Tabs primitive

### EntityModal (renamed from `EntityGraphModal` — D-09)

- Existing props plus: `headerExtras?: ReactNode` (right-side header slot for Maximize / Restore buttons), `size?: 'modal' | 'maximized'` (controls outer sizing), `onMaximize?: () => void`, `onRestore?: () => void`
- Children render in modal body slot (replaces hard-coded graph child).
- Backdrop, focus trap, Esc handling, click-outside dismissal stay in the shell (D-09).
- Modal size: `w-[92vw] h-[92vh] max-w-none rounded-lg shadow-2xl`
- Maximized size: applied via `data-overlay-takeover="true"` on the layout root + `position: fixed; inset: 0` on the modal — CSS toggle (D-11). When maximized, the modal body extends to `inset: 0` minus the takeover header band.
- ARIA: `aria-modal="true"`, `role="dialog"`, `aria-labelledby` pointing at the modal title.
- Dismissal: Esc / click-outside / ✕ all close fully regardless of size (LOCKED — D-12).

### useFullSourceOverlay() (new hook)

- Returns: `{ isOpen, size, cameFromModal, open, close, maximize, restore }`
- State: `useState<{ size: 'closed' | 'modal' | 'maximized'; cameFromModal: boolean }>`
- `open()` → `{ size: 'modal', cameFromModal: false }`
- `maximize()` → `{ size: 'maximized', cameFromModal: true }` (asserts current size === 'modal')
- `restore()` → `{ size: 'modal', cameFromModal: true }` (kept true — ensures Restore stays available on bounce maximize→modal→maximize)
- `close()` → `{ size: 'closed', cameFromModal: false }`
- Side effects: when size transitions to `'maximized'`, sets `document.documentElement.dataset.overlayTakeover = "true"`; clears on transition out. Cleans up on unmount.
- File location: `lib/hooks/useFullSourceOverlay.ts`

### Source-tab body (new — `components/editor/SourceTabBody.tsx`)

## Interaction States

### TabStrip

- **Default**: Detail tab active on first session load (LOCKED — SPEC Requirement 8)
- **Click**: swaps body content; updates `useSelectionStore.activePaneTab`; entity header persists
- **Keyboard**: Left/Right arrow keys move focus between tabs (standard ARIA tablist pattern); Home/End jump to first/last; Enter or Space activates the focused tab
- **Selection change while tab active**: tab stays active across entity selection (LOCKED — Requirement 6); body content re-renders for the new entity
- **Mode change (Standard ⇄ Developer) while Source tab active**: derived fallback via `useEffectiveTab(editorMode)` returns `'detail'` when active is `'source'` and mode is `'standard'`; store value is **never mutated** (LOCKED — D-15). Switching back to Developer restores Source tab.
- **Hover**: inactive tabs gain `hover:bg-slate-50 dark:hover:bg-slate-800/50` + label color shift; active tab has no hover change (already filled)
- **Focus-visible**: 2px primary ring inset (does not displace the bottom-border alignment)

### Source-tab toolbar

- **`↗ Open full source` click**: opens `EntityModal` at modal size; sets focus inside the modal (focus trap kicks in)
- **`⎘ Copy snippet` click**: copies snippet text to clipboard; shows toast "Snippet copied" (existing toast system)
- **Hover on `↗ Open full source`**: `bg-primary-50 dark:bg-primary-900/20`, label stays primary-600/400
- **Hover on `⎘ Copy snippet`**: `bg-slate-100 dark:bg-slate-800`, label slate-700/300

### Full-source overlay (Modal ⇄ Maximize ⇄ Restore round-trip)

- **Open**: modal size, `cameFromModal: false`, no Restore button visible. Focus moves into modal.
- **`⤢ Maximize`**: size → `'maximized'`, `cameFromModal: true`, `data-overlay-takeover="true"` on `<html>` → tree + detail panes hide via CSS. Restore button now visible.
- **`⊟ Restore`**: size → `'modal'`, `cameFromModal` stays `true` (so Restore appears again on next Maximize). `data-overlay-takeover` cleared.
- **Bounce maximize ⇄ restore**: symmetric, scroll position preserved (D-11 — Monaco component never unmounts).
- **Esc / click-outside / ✕**: from any size → fully closes; `cameFromModal` resets to `false`. (LOCKED — D-12.)
- **Selection change while overlay open**: overlay does NOT dismiss; body scrolls to new entity's lines, highlight re-applies (LOCKED — Requirement 10).
- **Tab persistence**: opening / closing / maximizing / restoring the overlay does NOT change `activePaneTab` (D-10).

### Empty states

- **Annotation property with no relationships** (Graph tab): centered icon + heading + body; backend returns `{nodes: [focus_only], edges: []}` (LOCKED — Requirement 11).
- **Source extractor cannot locate entity** (Source tab): centered icon + heading + body; toolbar still shows `↗ Open full source` so user can verify in full file (D-02).

### Reduced motion / high contrast

- All transitions on TabStrip (`transition-colors`) and modal open are suppressed under `@media (prefers-reduced-motion: reduce)` per existing `app/globals.css` rule.
- Focus ring widens under `@media (prefers-contrast: more)` per existing `app/globals.css` rule.

### Animation

- TabStrip active-state change: `transition-colors duration-150` (matches `EntityTabBar.tsx` precedent).
- Modal open: existing `EntityGraphModal` animation (fade + scale; not changed in this phase per D-09 + SPEC out-of-scope).
- Maximize ⇄ Restore: **no transition** — instantaneous size swap. CSS attribute toggle is intentionally abrupt to make the round-trip feel like a window-management action, not a graceful transform.
- Selection change while overlay open: Monaco's native scroll-to-line is the only motion; no fade.

## Accessibility

- **TabStrip**: `role="tablist"` on container; each tab `role="tab"`, `aria-selected`, `aria-controls` pointing at its panel id, `id` for the panel's `aria-labelledby`. Body panels are `role="tabpanel"` with `aria-labelledby` pointing at their tab.
- **Keyboard**: Left/Right arrows move focus between tabs; Home/End jump first/last; Enter or Space activates the focused tab. Tab key moves out of the tablist into the panel body (no roving tab-stop traps the user).
- **Active descendant**: focus-visible ring (2px primary) shows which tab has keyboard focus distinct from which tab is active (`aria-selected`).
- **EntityModal**: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` on the modal title; focus trap (existing — Radix Dialog); Esc dismisses.
- **Maximize / Restore buttons**: icon-only, `aria-label` per the copy table. Tooltip via existing tooltip pattern (title attribute or Radix Tooltip — match existing `EntityGraphModal` convention).
- **Source tab toolbar buttons**: `aria-label` on icon-only buttons; `Open full source` button has visible label, no aria override needed.
- **Screen-reader announcement on tab change**: tab swap is conveyed by `aria-selected` + focus move; an explicit `aria-live` is NOT added for tab changes (would create double announcements with most screen readers).
- **Screen-reader announcement on selection change while Source tab active** (auto-jump per Requirement 10): existing `useAnnounce()` hook from `ScreenReaderAnnouncer` fires "Source updated to {entity local name}" politely.
- **Annotation-property empty state**: heading uses `<h3>` semantic level (the parent panel uses `<h2>` for entity name).
- **Reduced motion**: see Animation section.
- **High contrast**: see Color section + existing `app/globals.css` rule.
